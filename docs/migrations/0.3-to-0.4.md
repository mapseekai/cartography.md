# Migrating 0.3.0 to 0.4.0

0.4.0 keeps YAML tokens, representative elements, and Markdown design intent. It changes the visual contract. Changing `version` alone is not a completed migration. The 0.4.0 parser rejects 0.3.0 documents; keep the original document until its meaning has been reviewed.

Review each affected element and record decisions outside the design document:

| Property | Required review |
|---|---|
| `size` | Confirm whether the old value was radius, diameter, icon width, or scale. The new value is the body's pre-rotation bounding-box long side; circles use diameter. Convert a known radius by doubling it. Preserve icon aspect ratio. |
| `strokeWidth` | The main stroke's full width excludes casing, outline, and halo. |
| `casingWidth` | Now thickness on each side. If the old value was bottom-line total width B and main width W, use (B − W) / 2, only after confirming that convention and compatible units. |
| `outlineWidth` / `haloWidth` | Outward thickness from the body or glyph contour; neither changes nominal body size. Confirm the historical convention. |
| Opacity | Preserve color alpha and part opacity; apply component opacity after internal drawing. Review old renderer compositing and report any approximation. |
| `offset` / `spacing` | Explain reference, direction and signs for nonzero offsets. Specify edge gap, center spacing, repeat spacing, or surround spacing. Keep signed offsets literal or in an extension, outside nonnegative standard groups. |
| Scale | Identify the base stage, permitted substitutions, visibility and invariants. Do not redefine tokens for a task or renderer. |
| State | Separate family role from critical/invalid/selected/hover states. Write explicit combined elements; preserve semantic state before interaction feedback. |

Separate size and spacing tokens from widths. Do not merge waterway and road tokens solely because their current values match. Review all typography fields and preserve unknown extensions. Source filenames, statistics, concrete scales, filters and conversion uncertainty belong in `INIT_REPORT.md` / `INIT_REPORT.json`, not the persistent design document.

Only after resolving these questions, update `version: "0.4.0"`, run lint, review the design, validate the target artifact, and review the rendered result. Report these four results separately. An automated migrator may make structurally certain edits and generate TODOs/reports; it must not guess historical size, casing, role/state, or scale baseline semantics.
